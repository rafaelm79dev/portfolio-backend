api-services-kafka

Two .NET services, each with its own database, that talk to each other only through Kafka.

Components

orders-apiCreates orders and asks inventory for the stock. Then it marks each order as confirmed or rejected.Port 8081
Orders databasePostgreSQLPort 5433
inventory-apiReserves the stock for an order, all lines or none, and answers.Port 8082
Inventory databasePostgreSQLPort 5434
KafkaThe only link between the two services. Two topics, orders.events and inventory.events, plus a dead-letter topic for each.Port 9092 · Kafka UI on port 8085

A service never reads the other one's database and never calls it over HTTP. They only share the message types.

How an order flows

  1. The client creates an order. orders-api saves it as Pending, together with the event to send, and answers right away.
  2. orders-api publishes OrderCreated in Kafka.
  3. inventory-api reads it and reserves the stock. It answers with StockReserved or StockRejected.
  4. orders-api reads the answer and sets the order to Confirmed or Rejected.
  5. The client asks for the order and sees the final status.

Until the answer arrives, the order is Pending. The two services agree after a short moment (eventual consistency).

When something fails

SituationWhat happens
Kafka is downOrders are still accepted. The events wait in the database and are sent when Kafka is back.
A message arrives twiceThe consumer recognises it and does nothing. The stock is not reduced twice.
Processing fails3 attempts. If all fail, the message goes to the dead-letter topic with the reason.
Two orders for the last unitOne gets the unit, the other is rejected. Stock never goes below zero.

Run it

docker compose up --build starts everything. See the README for the commands to try it and for what to look at in Kafka UI.

Known limitations

  • If an answer ends in the dead-letter topic, the order stays Pending. Nothing reprocesses it.
  • There is no cancel flow, so reserved stock is never released.
  • No authentication, and Kafka and the databases have no login or encryption: use it on a closed network.
